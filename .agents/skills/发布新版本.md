# 发布新版本准备

本流程只做**发布前准备**，不执行发布。

## 硬性边界

- 禁止执行 `git commit`、`git tag`、`git push`、`npm publish`，也禁止把运行时文件复制到全局插件目录。这些是用户的发布动作。
- 禁止在源码里写死版本号。唯一真相源是 `package.json` 的 `version`，运行时通过 `version.ts` 导出。
- 新版本号必须由改动内容推导，不能随便自增，也不能跳过确认直接选一个。
- 全部检查通过后，把发布命令列给用户，明确说明「尚未发布」。

## 步骤

### 1. 确定新版本号

查看自上一个版本以来的实际改动：

- `CHANGELOG.md` 的最后一个版本小节。
- 若仓库有 git 历史，用 `git log <tag>..HEAD --oneline`；没有 git 时直接阅读当前代码与用户说明。

按语义化版本判断：

| 改动性质 | 版本变化 | 0.x 阶段的例子 |
| :--- | :--- | :--- |
| 破坏性变更：配置项改名/删除、事件语义变化、导出接口不兼容 | major | `0.1.0` → `0.2.0`（0.x 阶段按 SemVer 允许把破坏性变更放到 minor） |
| 新增功能：新事件、新配置项、TUI 新指令 | minor | `0.1.0` → `0.2.0` |
| 修复、文档、内部重构、依赖升级 | patch | `0.1.0` → `0.1.1` |

有歧义时先给出建议版本和理由，让用户确认后再继续。

### 2. 更新版本号

```powershell
npm version <新版本> --no-git-tag-version
```

该命令同时更新 `package.json` 与 `package-lock.json`。不要手改其中一个。

### 3. 更新 CHANGELOG.md

在文件顶部新增小节，日期用当天日期：

```markdown
## <新版本> - <YYYY-MM-DD>

- 新增：……
- 变更：……
- 修复：……
```

只写用户可感知的变化，内部琐碎改动可以合并成一条。条目沿用中文。

### 4. 检查文档是否需要跟随

- `README.md`：配置项表格、事件表、文件清单、已验证的 OpenCode 版本、TUI 指令说明。
- `.agents/skills/opencode-v2-plugin-api.md`：如涉及 V2 API 或飞书接口的新认知。
- 新增源码文件时同步 README 的文件清单。

### 5. 运行自动检查

```powershell
bun run check
```

等价于 `tsc --noEmit && bun test`。其中 `test/version.test.ts` 会校验：

- `VERSION` 与 `package.json` 一致；
- 版本号是合法 SemVer；
- `package-lock.json` 两个版本字段与 `package.json` 一致；
- `CHANGELOG.md` 包含当前版本的小节。

任何一项失败都先修复，不得跳过。

### 6. 验证可打包

```powershell
bun build ./index.ts ./tui.tsx --target=bun --outdir .tmp-release --external @opencode/plugin --external @opentui/core --external @opentui/solid --external solid-js
Remove-Item .tmp-release -Recurse -Force
npm pack --dry-run
```

确认两个入口都能打包且无警告，并确认 `npm pack --dry-run` 的清单只包含 `files` 白名单与文档。`bun build` 用于提前发现 JSON 导入、类型导入等运行时解析问题。

### 7. 汇报并交给用户发布

汇报内容：

- 旧版本 → 新版本，以及版本级别判断理由；
- CHANGELOG 条目与文档改动清单；
- 检查结果（tsc、测试数量、打包与 `npm pack --dry-run` 清单）；
- 用户手动发布的命令示例：

```powershell
npm login --registry=https://registry.npmjs.org/
npm publish --tag next --registry=https://registry.npmjs.org/
# 用 opencode plugin add opencode-feishu-cards@next 验证安装后的包
npm publish --registry=https://registry.npmjs.org/
git tag v<新版本>
git push --follow-tags
```

发布前必须用 `next` 预发布标签验证安装后的包，因为 `opencode plugin add` 不接受 tarball。最终 `npm publish`、打标签与推送由用户执行。
